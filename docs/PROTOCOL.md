# Protocol and implementation mapping

## Failure boundary

A boundary contains a task, failed command, visible command result, before/after persistent state, external-fault schedule, and an independent task oracle. Admission requires nonzero execution, a changed semantic state projection, and an unsatisfied completion contract. Merely finding changed bytes or a nonzero status is insufficient.

In the six fixtures, the operation contract and final task contract coincide. The general protocol distinguishes command completion from eventual task completion.

## State conditions

| Condition | Construction in the reference engine |
|---|---|
| PRE | Restore the captured pre-command state |
| REAL | Restore the captured actual post-failure state |
| UNDO | Restore REAL; apply the certified delta in reverse |
| REINTRO | Restore PRE; apply the certified delta forward |
| WORKTREE | Restore PRE; apply only demo worktree-payload differences |
| OUTSIDE | Restore PRE; apply the complementary declared resource differences |
| POST | Restore PRE; clear the external fault; execute the unchanged original command and verify completion |

UNDO and REINTRO apply stored file differences. A delta is rejected when the current state differs from its preconditions. Fixture oracles also check prior work.

POST is unavailable for the intrinsically inconsistent patch and database commands. Correcting their input would change the command/patch and is not a legal corresponding POST intervention. The other four fixtures expose a one-shot external interruption. Its schedule is reset independently and identically for each branch; it is not based on branch wall-clock speed.

## State boundary

`StateStore` captures the **entire declared fixture directory**, including hidden files, installation targets, virtual environments, caches and databases. It stores content-addressed file bytes, path names, file modes, modification times and symlink targets. Hard links and special files are rejected. Deltas include additions, modifications and deletions. Snapshot material and evaluator code remain outside the task directory.

The demo semantic projection compares paths, bytes, modes and link targets; it excludes timestamps from equality. Modification times are restored. Oracle execution uses separate directory clones; changes in these clones are not copied into task state.

The WORKTREE/OUTSIDE split is fixture-declared: `packages/`, `.venv/`, `cache/`, `records.sqlite`, and `.git/` are outside the payload. It is a resource partition inside the task directory. Hybrid states pass structural snapshot reconstruction checks. The demo does not reproduce the original pre-certified 20/20/20 coverage strata.

## Information control

Each pair reuses the same task, failed argv, semantic history, selected feedback, working-directory name, resource setting and repeat seed. The request contains neither state-condition labels nor certified deltas, reference repairs, or oracle checks. State is restored into the same physical task path between branches. The recorded failed response is replayed rather than regenerated per branch.

The engine records two hashes:

- `first_request_sha256`: canonical serialized boundary input before any permitted new observation. Pair analysis requires equality within a controller/block.
- `first_model_request_sha256`: the actual first serialized adapter request. For Native this precedes tool observations. For Retry-1 it follows the forced retry and can legitimately differ if that retry observed different state. The boundary hash supplies the pre-observation equality check.

Raw feedback is captured command output; demo neutral feedback is a reviewed failure-class summary; terse feedback keeps tool identity, class and status. These simplified neutral messages do not replicate the original site's unavailable diagnostic-preserving rewrites.

## Scoring

The oracle checks `success = functional AND state_obligations` in a clone. A missing state obligation does not erase a successful functional check. This enables functional-only rescoring without rerunning an agent. `silent_error = completion_claim AND NOT success`; explicit inability is never treated as a completion claim. Budget exhaustion is scored on the current state and remains in the denominator.

The package example checks actual imports and distribution metadata. The virtual-environment example checks an executable isolated interpreter and its required readiness record. Database validation checks exact row obligations, preserved prior data and integrity. Build validation loads generated bytecode, evaluates its product and checks source hashes. Generation checks required output content and its index. Patch checks final content, reject removal and prior work.

## Controllers and budgets

The reference engine implements the paper's strategy structure. Native resumes; Retry-1 runs the exact failed argv once in the same cwd/environment with no cleanup; Inspect-N admits at most N structured reads; Read-3 reveals only an immutable task-independent fixture. Arbitrary shell is never accepted as an initial read-only inspection.

Reflexion allows a 512-token reflection at the initial failure and at most two later failed-command triggers, retaining at most three memories. Self-Refine generates a 512-token candidate, then two 256-token-feedback/512-token-revision rounds and executes only the final revision. Every deliberation, rejected action, tool operation and final response consumes a reference-engine action. The original public frameworks' native action accounting was not provided.

Default limits are 40 actions, 16,000 generated tokens and 1,800 seconds, with a 300-second command timeout. Resource-grid budgets jointly scale actions, tokens and time. Token accounting uses adapter-reported generated counts and generation limits. Tool output is capped at 8 KiB, without tokenizer-specific truncation. Inspection output is capped at 2 KiB.
